# Lectern app audit, September 5, 2026

I found and fixed bugs in the shiur subscription pipeline, transcription and generation coordination, audio retention, and file imports. The changes are in the working tree. They have not been installed over your running app or published as a release.

| Area | Problem and fix |
| --- | --- |
| Empty subscription feeds | An empty first check caused the next nonempty check to establish another baseline, silently skipping the first new shiur. Baseline detection now uses the successful-check timestamp. |
| Recent-shiur backlog | The initial import chose the first five feed entries, even if those were the oldest. It now chooses the five newest by publication date and processes them oldest first. |
| Interrupted feed checks | Feed validators and seen IDs could be saved before the remaining imports were queued. A restart could then receive “not modified” and lose those imports. The full queue and feed checkpoint now save together before downloading. |
| Course assignment | Pending imports did not save their destination course. The queue now persists the course identifier and resolves it on resume, with a subscription-course fallback for older items. |
| Duplicate imports | Deduplication only checked finished lecture records. Overlapping feeds could create multiple pending or failed jobs for the same shiur. Checks now reuse the existing queue record, filter repeated feed entries, and serialize processing of the same source. Resuming a download also checks for an already-imported lecture. |
| Transcription handoff | Automation watched the lecture status before a queued transcription task had started, then returned without advancing to notes. It now waits for that lecture to leave the transcription queue and checks the result. Cancellation exits the wait. |
| Incomplete transcripts | A partial or empty transcript artifact could count as completed work. Completion now requires ready status and nonempty text. An empty artifact no longer prevents the transcription service from retrying. |
| Competing generation jobs | Manual generation checked only for another manual task and could overlap automatic subscription generation. Both entry points now respect the shared active-job state. |
| Failed imports | Subscriptions did not expose failed pipeline items or a retry action. They now show failure details and a Retry button that resumes the appropriate stage. |
| Audio retention | Retention could delete the original audio after only a partial transcript had been saved. It now requires a completed transcript and only marks a recording pruned after deletion succeeds or the file is already absent. |
| Rapid audio imports | Imported filenames had only second-level timestamps. Two imports in one second collided. Filenames now include a UUID. |
| Failed bundle imports | A bundle import that failed while copying a reference could leave a partial lecture, artifacts, and copied files behind. Failure cleanup now removes the records and files created by that import while preserving existing lectures. |

Subscription checks also do less repeated work. They decode the seen-ID set once for filtering and update it once per response. Lecture, subscription, and queued-item lookups use database predicates with a one-result limit instead of loading every row. I have not measured a user-visible speedup, so there is no timing claim.

The test target now compiles the actual application services. Previously, several subscription tests only checked model values and could not catch pipeline failures. I added 15 tests using in-memory stores, temporary audio files, fixture feeds, and a local dummy process. Eleven of those tests reproduced failures before their fixes. The additional checks cover complete queue persistence before downloading, saved course identifiers, duplicate entries, successful retention, and retry behavior.

Validation: the final full test run passed all 132 tests, comprising 73 XCTest tests and 59 Swift Testing tests. This includes the 15 new regression tests. `git diff --check` passed, and `xcodegen generate` regenerated the checked-in project after the test-target change. The macOS arm64 Release build also passed.

The final test command was `xcodebuild -scheme Lectern -destination 'platform=macOS,arch=arm64' test`. The Release check uses `xcodebuild -scheme Lectern -configuration Release -destination 'platform=macOS,arch=arm64' build`.

The deepest review covered subscriptions and their import, transcription, generation, and retention dependencies. I also inspected Canvas and Google Docs sync entry points and bundle import/export code, and ran the existing updater, Canvas, transcription-provider, notes, export, notification, and YU Torah tests. This was a code and automated-test audit, not an exhaustive review of every screen or a dedicated security audit.

Remaining limits: I did not run a complete live scheduled subscription through remote audio download, a real transcription provider, and generated notes; test sleep/wake scheduling on a sleeping Mac; visually exercise the new Retry controls; or make live Canvas, Google Docs, or Anki writes. Existing YU Torah search tests did run against the network. The pipeline tests use controlled inputs so failure and restart-related states are repeatable. The fixes prevent future failures; they do not reconstruct previously deleted audio or automatically recover shiurim skipped by an earlier baseline.
